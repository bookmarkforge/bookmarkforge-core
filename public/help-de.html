Troubleshooting — die meisten Probleme in 30 Sekunden

Vault gesperrt / falsches Passwort

Passwörter sind Groß-/Kleinschreibung- und Leerzeichen-sensitiv. Wenn Sie das Tastaturlayout gewechselt haben (z. B. AZERTY→QWERTY), tippen Sie langsam neu. Nach 5 fehlgeschlagenen Entsperrversuchen warten Sie 1 Minute. Wenn Sie das Passwort verloren haben, verwenden Sie die 24-Wort-Wiederherstellungsphrase, die bei der Vault-Erstellung einmal angezeigt wurde (BF-E101). Ohne diese Phrase ist eine Wiederherstellung nach Design unmöglich — wir haben keinen Backdoor.

Browserspeicher voll

IndexedDB-Quota ist browserabhängig (typisch 60–80 % der Festplatte). Wenn voll, schlagen Speichervorgänge mit BF-E103 fehl. Lösung: Einstellungen → Speicher → Datenbank komprimieren, dann AI-Cache leeren. Oder Backup exportieren (.bmf) → Alte Vektoren löschen. Prüfen Sie Speicher % im Diagnosebericht — ab 80 % wird ein Banner angezeigt.

P2P-Sync verbindet nicht

Beide Geräte müssen gleichzeitig online und entsperrt sein (WebRTC). Standardmäßig kein TURN-Relay — einige Unternehmensnetzwerke blockieren P2P. Versuch: Beide im gleichen WLAN → QR-Pairing → App geöffnet halten. Wenn BF-E105 erscheint, testen Sie Hilfe → Diagnose → P2P (WebRTC) — wenn „nicht verfügbar“ steht, blockiert Ihr Browser/Netzwerk WebRTC.

Local AI (WebLLM) läuft nicht

Benötigt WebGPU + ca. 4 GB freien RAM + Pro-Lizenz. Prüfen Sie Hilfe → Diagnose → WebGPU/WebLLM. Wenn BF-E106: Aktualisieren Sie Chrome/Edge auf die neueste Version, aktivieren Sie chrome://flags/#enable-unsafe-webgpu oder wechseln Sie zu Ollama (beliebiges lokal laufendes Modell — auch hier kein API-Key erforderlich).

Langsame Suche oder Import

Der erste Import baut HNSW-Vektoren auf — CPU-intensiv. Lassen Sie den Tab geöffnet. Für 10.000+ Lesezeichen verwenden Sie Einstellungen → Erweitert → Neuverarbeitung erzwingen. Falls weiterhin langsam: Diagnosebericht kopieren zeigt vectorIndexLoad und Abfragelatenz.

Fehlercodes BF-E* — Code kopieren, Lösung finden

Jeder kritische Fehler zeigt einen Code wie BF-E101. Klicken Sie auf den Code in der App oder suchen Sie hier danach.

CodeBedeutungLösung
BF-E101Vault-Passwort vergessen / Wiederherstellungsphrase erforderlichWir können Passwörter nicht wiederherstellen. Bei der Vault-Erstellung wird einmalig eine 24-Wort-Phrase angezeigt — notieren Sie diese auf Papier. Verwenden Sie sie zur Wiederherstellung. Ohne Phrase ist der Vault unrecoverable. Kein Ticket kann dies rückgängig machen.
BF-E102Vault gesperrt / falsches PasswortGeben Sie das Passwort exakt ein. Nach 5 Fehlversuchen warten Sie 60 s. Wenn Sie das Passwort kürzlich geändert haben, probieren Sie das vorherige — die Rotation behält das letzte Salt für Rollback.
BF-E103Speicherplatz überschrittenGehen Sie zu Einstellungen → Speicher: Datenbank komprimieren + AI-Cache leeren. Exportieren Sie bei Bedarf ein .bmf-Backup. Siehe Troubleshooting §Speicher.
BF-E104IndexedDB blockiert / privates SurfenIndexedDB ist im privaten/Inkognito-Modus oder durch Speicherpolicy blockiert. Verwenden Sie ein normales Fenster. Prüfen Sie Hilfe → Diagnose → Speicher.
BF-E105P2P / WebRTC nicht verfügbarBrowser oder Netzwerk blockieren WebRTC. Probieren Sie einen anderen Browser/Netzwerk, deaktivieren Sie eine strenge Firewall oder verwenden Sie Export/Import statt Live-Sync.
BF-E106Local AI (WebLLM) kann auf diesem Gerät nicht ausgeführt werdenBenötigt WebGPU + shader-f16 + 4 GB RAM + Pro. Aktualisieren Sie den Browser oder verwenden Sie Ollama / Cloud-Provider mit eigenem Key.
BF-E107Backup-Import fehlgeschlagen (falsches Passwort / beschädigte Datei)Für .bmf (verschlüsselt) benötigen Sie das Export-Passwort, nicht das Vault-Passwort. Für JSON stellen Sie sicher, dass die Datei nicht abgeschnitten ist.
BF-E201Pro-Lizenz ungültig / AblaufprüfungPrüfen Sie Einstellungen → Pro: Geben Sie den Key erneut ein. Offline-Prüfungen werden gecacht; einmal verbinden, um über Whop neu zu validieren.
BF-E202Free-Limit erreicht (2.500 Lesezeichen)Free ist auf 2.500 begrenzt. Löschen Sie Einträge oder upgraden Sie auf Pro Lifetime v1 für unbegrenzt. Export ist immer verfügbar.

Support-Tipp: Durch Klicken auf Diagnose kopieren im Fehler werden Code + Kontext in einem Klick kopiert — fügen Sie ihn in Ihre GitHub Discussion oder E-Mail ein.

Redigierten Diagnosebericht kopieren — was Sie an Support senden

In der App: Einstellungen → Erweitert (oder Hilfe → Diagnose) → Diagnose kopieren. Er sieht so aus — keine Vault-Inhalte, keine URLs, keine Prompts:

BookmarkForge v1.0.0 | Chrome 126 | Vault: 847 Lesezeichen, 12 Docs Speicher: 42% (IndexedDB OK) | Letztes Backup: vor 2 Tagen (.bmf verschlüsselt) P2P: nicht verbunden | Sync: nie | Local AI: WebLLM nicht geladen Fehler: 0 in den letzten 7 Tagen | BF-E: keine | Build: a1b2c3d

Enthält: App-Version, Browser, Zähler (Lesezeichen/Docs/Vektoren), Speicher % + Quota, P2P-Status, AI-Status, Fehleranzahl & letzter BF-E-Code, Build-Hash. Verwendet einen gesalzenen Hash der IP — wir speichern niemals IP. Siehe Datenschutz §3/§6.

Wenn Sie die App nicht öffnen können: Geben Sie Browser + OS + Schritte zur Reproduktion + den angezeigten BF-E*-Code an. Das reicht für 90 % der Tickets.
