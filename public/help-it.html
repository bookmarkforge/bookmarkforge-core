Risoluzione problemi — la maggior parte dei casi in 30 secondi

Vault bloccato / password errata

Le password distinguono maiuscole/minuscole e spazi. Se hai cambiato layout (es. AZERTY→QWERTY), digita lentamente. Dopo 5 tentativi di sblocco falliti, attendi 1 minuto. Se hai perso la password, usa la frase di recupero da 24 parole mostrata una sola volta alla creazione del vault (BF-E101). Senza di essa, il recupero è impossibile per progettazione — non abbiamo alcuna backdoor.

Memoria del browser piena

La quota di IndexedDB dipende dal browser (generalmente dal 60% all'80% del disco). Quando è piena, il salvataggio fallisce con BF-E103. Soluzione: Impostazioni → Archiviazione → Compatta database poi Pulisci cache AI. Oppure Esporta backup (.bmf) → Elimina vettori vecchi. Verifica la percentuale di archiviazione nella diagnostica — sopra l'80% mostriamo un avviso.

Sincronizzazione P2P non si connette

Entrambi i dispositivi devono essere online e sbloccati contemporaneamente (WebRTC). Di default non c'è un relay TURN — alcune reti aziendali bloccano il P2P. Prova: entrambi sulla stessa Wi-Fi → associazione tramite QR → mantieni l'app aperta. Se BF-E105, testa Aiuto → Diagnostica → P2P (WebRTC) — se dice non disponibile, il browser/rete blocca WebRTC.

AI locale (WebLLM) non in funzione

Richiede WebGPU + ~4 GB di RAM libera + licenza Pro. Verifica Aiuto → Diagnostica → WebGPU/WebLLM. Se BF-E106: aggiorna Chrome/Edge all'ultima versione, abilita chrome://flags/#enable-unsafe-webgpu, oppure passa a Ollama (qualsiasi modello locale, senza chiave API).

Ricerca o importazione lente

Il primo import crea gli indici vettoriali HNSW — operazione intensa per la CPU. Mantieni la scheda aperta. Per oltre 10k segnalibri usa Impostazioni → Avanzate → Forza rielaborazione. Se persiste, la copia diagnostica mostra vectorIndexLoad e la latenza delle query.

Codici di errore BF-E* — copia il codice, vai alla soluzione

Ogni errore critico mostra un codice come BF-E101. Fai clic sul codice nell'app o cercalo qui.

CodeSignificatoSoluzione
BF-E101Password del vault dimenticata / frase di recupero richiestaNon possiamo recuperare le password. Alla creazione del vault viene mostrata una frase da 24 parole una sola volta — scrivila su carta. Usala per reimpostare. Senza frase, il vault è irrecuperabile. Nessun ticket potrà recuperarlo
BF-E102Vault bloccato / password errataDigita la password esattamente. Dopo 5 tentativi falliti attendi 60 secondi. Se hai cambiato password di recente, prova quella precedente — la rotazione mantiene l'ultimo salt per il rollback.
BF-E103Quota di archiviazione superataVai su Impostazioni → Archiviazione: compatta il database + pulisci la cache AI. Se necessario, esporta un backup .bmf. Vedi Risoluzione problemi §Archiviazione.
BF-E104IndexedDB bloccato / navigazione in incognitoIndexedDB è bloccato in modalità privata/incognito o da una policy di archiviazione. Usa una finestra normale. Verifica Aiuto → Diagnostica → Archiviazione.
BF-E105P2P / WebRTC non disponibileIl browser o la rete bloccano WebRTC. Prova un altro browser/rete, disabilita il firewall restrittivo o usa Esporta/Importa invece della sincronizzazione in tempo reale.
BF-E106AI locale (WebLLM) non può essere eseguita su questo dispositivoRichiede WebGPU + shader-f16 + 4 GB di RAM + Pro. Aggiorna il browser, oppure usa Ollama / un provider cloud con la tua chiave personale.
BF-E107Importazione backup fallita (password errata / file corrotto)Per i file .bmf (crittografati) serve la password di esportazione, non quella del vault. Per JSON, assicurati che il file non sia stato troncato.
BF-E201Licenza Pro non valida / controllo scadutoVerifica Impostazioni → Pro: reinserisci la chiave. I controlli offline vengono memorizzati nella cache; riconnettiti una volta per rivalidare tramite Whop.
BF-E202Limite Free raggiunto (2,500 segnalibri)Il piano Free è limitato a 2,500 segnalibri. Elimina alcuni segnalibri o passa a Pro Lifetime v1 per averli illimitati. L'esportazione è sempre disponibile.

Consiglio per il supporto: cliccando Copia diagnostica sull'errore copi automaticamente codice + contesto in un unico clic — incollalo nella tua discussione su GitHub o via email.

Copia un report diagnostico redatto — cosa incollare al supporto

Nell'app: Impostazioni → Avanzate (o Aiuto → Diagnostica) → Copia diagnostica. Apparirà così — nessun contenuto del vault, nessun URL, nessun prompt:

BookmarkForge v1.0.0 | Chrome 126 | Vault: 847 bookmarks, 12 docs Storage: 42% (IndexedDB OK) | Last backup: 2 days ago (.bmf encrypted) P2P: not connected | Sync: never | Local AI: WebLLM not loaded Errors: 0 last 7d | BF-E: none | Build: a1b2c3d

Cosa contiene: versione app, browser, conteggi (segnalibri/documenti/vettori), percentuale e quota di archiviazione, stato P2P, stato AI, conteggi errori e ultimo codice BF-E, hash di build. Usa un hash con salt dell'IP — non memorizziamo mai l'IP. Vedi Privacy §3/§6.

Se non riesci ad aprire l'app: includi browser + sistema operativo + passaggi per riprodurre il problema + il codice BF-E* sullo schermo. È sufficiente per il 90% dei ticket.
