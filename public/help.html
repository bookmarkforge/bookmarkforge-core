Troubleshooting — most issues in 30 seconds

Vault locked / wrong password

Passwords are case- and whitespace-sensitive. If you changed layout (e.g. AZERTY→QWERTY) retype slowly. After 5 failed unlocks, wait 1 minute. If you lost the password, use the 24-word recovery phrase shown once at vault creation (BF-E101). Without it recovery is impossible by design — we have no backdoor.

Browser storage full

IndexedDB quota is per-browser (typically 60–80% of disk). When full, saves fail with BF-E103. Fix: Settings → Storage → Compact database then Clear AI cache. Or Export backup (.bmf) → Delete old vectors. Check storage % in diagnostic — above 80% we show a banner.

P2P sync not connecting

Both devices must be online and unlocked at the same time (WebRTC). No TURN relay by default — some corporate networks block P2P. Try: both on same Wi-Fi → QR pair → keep app open. If BF-E105, test Help → Diagnostics → P2P (WebRTC) — if it says unavailable, your browser/network blocks WebRTC.

Local AI (WebLLM) not running

Requires WebGPU + ~4 GB free RAM + Pro license. Check Help → Diagnostics → WebGPU/WebLLM. If BF-E106: update Chrome/Edge to latest, enable chrome://flags/#enable-unsafe-webgpu, or switch to Ollama (any model you run locally — no API key needed either).

Slow search or import

First import builds HNSW vectors — CPU heavy. Keep tab open. For 10k+ bookmarks use Settings → Advanced → Force reprocess. If persists, Copy diagnostic shows vectorIndexLoad and query latency.

Error codes BF-E* — copy the code, jump to the fix

Every critical error shows a code like BF-E101. Click the code in the app or search it here.

CodeMeaningFix
BF-E101Vault password forgotten / seed phrase requiredWe cannot recover passwords. At vault creation we show a 24-word phrase once — write it on paper. Use it to reset. No phrase = vault unrecoverable. No ticket will recover it.
BF-E102Vault locked / wrong passwordRetype password exactly. After 5 failures wait 60s. If you rotated password recently, try the previous one — rotation keeps last salt for rollback.
BF-E103Storage quota exceededGo to Settings → Storage: Compact DB + Clear AI cache. Export .bmf backup if needed. See Troubleshooting §Storage.
BF-E104IndexedDB blocked / private browsingIndexedDB is blocked in private/incognito or by storage policy. Use a normal window. Check Help → Diagnostics → Storage.
BF-E105P2P / WebRTC unavailableBrowser or network blocks WebRTC. Try another browser/network, disable strict firewall, or use Export/Import instead of live sync.
BF-E106Local AI (WebLLM) cannot run on this deviceNeeds WebGPU + shader-f16 + 4 GB RAM + Pro. Update browser, or use Ollama / cloud provider with your own key.
BF-E107Backup import failed (wrong password / corrupt file)For .bmf (encrypted) you need the export password, not the vault password. For JSON, ensure file wasn't truncated.
BF-E201Pro license invalid / expired checkCheck Settings → Pro: re-enter key. Offline checks cache; reconnect once to re-validate via Whop.

Copy a redacted diagnostic — what you paste to support

In the app: Settings → Advanced (or Help → Diagnostics) → Copy diagnostic. It looks like this — no vault content, no URLs, no prompts:

BookmarkForge v1.0.0 | Chrome 126 | Vault: 847 bookmarks, 12 docs Storage: 42% (IndexedDB OK) | Last backup: 2 days ago (.bmf encrypted) P2P: not connected | Sync: never | Local AI: WebLLM not loaded Errors: 0 last 7d | BF-E: none | Build: a1b2c3d

What it contains: app version, browser, counts (bookmarks/docs/vectors), storage % + quota, P2P status, AI status, error counts & last BF-E code, build hash. Uses a salted hash of IP — we never store IP. See Privacy §3/§6.

If you cannot open the app: include browser + OS + steps to reproduce + the BF-E* code on screen. That's enough for 90% of tickets.
